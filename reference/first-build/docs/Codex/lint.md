# Effect and TypeScript checks

`bun run lint` runs Oxlint with TypeScript type checking, type-aware safety rules, the full community `oxlint-plugin-effect` recommended preset, and the official Foldkit plugin for frontend code. Unsafe values, unchecked promises, assertions, non-exhaustive branches, raw asynchronous orchestration and unscoped resources fail the check. `bun run typecheck` independently checks the complete workspace using the native TypeScript compiler.

Two purely stylistic Effect rules are intentionally omitted: `noTernary` (short value selections remain readable) and `noShapeInSymbolNames` (public domain names such as `MarketView` describe their purpose). `noNullish` is omitted only in the contract, surfaces and market DTO schema modules because their existing JSON wire formats explicitly represent absent measurements as null. Domain state uses `Option`; transport codecs own conversion to nullable fields. Other exceptions require a narrow directive explaining the external boundary and why the preferred Effect API does not apply.

The Effect lint package is community maintained. It is not represented as an official Effect Foundation tool. Foldkit's rules are maintained with Foldkit. Dependency versions are pinned in `package.json` and `bun.lock`.

Official native Effect diagnostics are enabled through `@effect/tsgo` in both the patched TypeScript compiler and patched Oxlint type-aware engine. `strict`, `maintainers` and `effect-native` presets are enabled; warning levels are promoted to errors. The `prepare` script reapplies the supported binary integration after a dependency install. TypeScript 7.0.2, Oxlint 1.87.0 and oxlint-tsgolint 7.0.2003 are the supported versions for the pinned integration.

`allowedUnstableApis` acknowledges the pinned native module families deliberately reviewed and adopted by the application: AI, CLI, HTTP, HttpApi, RPC, SQL/Model, reactivity, devtools and observability. This acknowledges their version-sensitive status without disabling the rule for other dependencies. Internal exports that expose such native APIs must retain an accurate stability annotation. The renderer's exact DTO type module also permits null because the Three/Foldkit imperative callback boundary uses that transport convention; renderer state still uses Option.

The project-specific `floor/*` rules are native AST visitors built with the pinned `effect-oxlint` package (`CustomRule.define`, `Visitor`, and `Plugin.define`). They check imports, re-exports, dynamic imports, type imports and CommonJS imports. The contract remains isolated to Effect and its own modules; signing cannot import agents or inference; production cannot import tests, fixtures or recordings; sibling frontend features cannot import one another. Computed production module specifiers are rejected because they would make those boundaries uncheckable. A source file's text is never scanned with regular expressions to infer imports.

`lint:rules` bundles the typed plugin into `node_modules/.cache/floor-lint` before Oxlint loads it. This generated host adapter is disposable; the rule source and tests live together under `scripts/lint`. The plugin harness runs inside native `@effect/vitest` tests and checks allowed as well as rejected edges. Built-in Effect rules continue to enforce runtime, JSON, clock, filesystem and process boundaries; the project plugin does not duplicate or weaken them.

Tests run under Bun so the production SQLite driver is exercised directly. Bun 1.4.0 matches the checked runtime and the pinned toolchain. Process primitives are included among the reviewed native module families for the local development supervisor.
