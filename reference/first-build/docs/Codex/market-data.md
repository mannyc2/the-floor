# Market readings

The Base reader captures fourteen configured markets: six constant-product pools, seven concentrated-liquidity pools, and one Virtuals bonding curve. Addresses select what to read; discovery API prices and volumes never enter a market snapshot. Every contract call uses the same block number, and the reader rechecks its hash after collection. Failed pools are omitted with an explicit partial-reading count. Failed swap-log requests produce absent flow measurements, while successful empty windows produce measured zeros.

Concentrated-liquidity prices come from `sqrtPriceX96`, corrected for both token decimals and quote orientation. Token balances do not determine that price. The displayed band is only the current observed tick interval; the application does not claim to have collected the full liquidity distribution. Dollar marks use another pool observed in the same block: WETH/USDC or VIRTUAL/USDC. The current swap window is distinct from a 24-hour volume, which remains unavailable unless actually measured.

The Virtuals curve is the Solara pair `0x61C4823734285CCe741EF5caBb79B494Cf373516`, returned by registry index 1 of bonding proxy `0xf66dea7b3e897cd44a5a231c61b6b4423d613259`. Each reading checks that the pair and token match the registry. Virtual reserves determine marginal price; `balance()` and `assetBalance()` provide actual inventory. Graduation measures tokens sold toward the initial supply minus the remaining-token threshold. The reading records this basis and its token unit explicitly, along with both virtual reserve integers. The implementation follows the protocol's published [Bonding](https://github.com/Virtual-Protocol/protocol-contracts/blob/main/contracts/fun/Bonding.sol), [FPair](https://github.com/Virtual-Protocol/protocol-contracts/blob/main/contracts/fun/FPair.sol) and [FRouter](https://github.com/Virtual-Protocol/protocol-contracts/blob/main/contracts/fun/FRouter.sol) sources. Inclusion demonstrates a measured mechanism and is not an assessment of the token.

`bun packages/markets/src/capture.ts testing/recordings/base-day.json 24` captures 25 hourly block readings. The recording preserves chain block hashes, timestamps, raw reserves and provenance. It contains no interpolated prices or generated trades. Zero hours captures only the latest block. Runtime fallback labels these snapshots as recordings and never relabels them live.

Native Effect services own RPC access and snapshot retention. A cache retained by the service coalesces concurrent refreshes and expires after fifteen seconds; metadata keys are structural address/block values. Tests replace only the external chain boundary, exercise the production recording codec and history logic, and advance the native TestClock to verify cache expiration.

District tiers are computed from retained observations, persisted per source block and replayed with that block. Daily activity is a lower bound from non-overlapping measured flow windows inside the prior 24 hours; two-minute samples are never extrapolated into daily trades. Missing or partial coverage can establish sufficient activity but cannot establish inactivity. Unknown new markets remain stalls; observed low liquidity can still demote an existing works. Liquidity ranks and 20% hysteresis determine works and towers after those checks. The bundled sparse recording does not establish enough daily trades for promotion, so its initial atlas correctly contains stalls. A chain-hash replacement invalidates that block's tier assignment and every later dependent assignment. Tests verify overlap, gaps, replay, SQLite restart and this reorg invalidation.

History is a native `MarketHistory` capability. Production uses the same scoped SQLite client and migrations as the workspace; captures and isolated tests explicitly use the in-memory layer. `FLOOR_HISTORY_BLOCKS` controls the number of recent unpinned blocks retained (default 2,048, valid range 1–10,000). New observations commit before an Atlas response or stream publication. Storage contains each block’s measurements once; price charts are derived from retained blocks rather than recursively embedding earlier charts. On startup `FLOOR_RECORDING` (default `data/base-day.json`) is imported idempotently: existing observations win over the bundled recording, and imported history is subject to the same bound. A failed live RPC falls back to the newest retained observation with an explicit historical label.

Capturing a plate pins its exact source block in the same SQL transaction as the plate. Pinned sources survive regular retention and database restart. A later observation with a conflicting hash cannot replace pinned evidence. Restart tests close and reopen a real SQLite file, check exact decoded readings and flow windows, and prove that an abandoned plate transaction rolls back its pin. Recorded edge layers in `packages/markets/src/testing` replace only the external chain reader while using the production history and cache.
